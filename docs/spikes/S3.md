# S3: `image()` reload

**Verdict: Pass.** A new file name always shows the new picture. A file overwritten in place under `data/` stays stale; under `mods/` it updates.

Run 2026-11-19 (KST) in the live Herdr 0.1.16 window, space `lazuli-spike`, tab `lz-s3`, mod `lz-spike` view `s3`.

## Question

Does `image(path)` show new pixels when lazuli writes a new JPEG? Two cases matter:

- **Required:** a new, unique file name (PDF pages, Markdown image cache).
- **Noted:** the same file overwritten in place.

## Steps

1. The view draws three 240×160 `image()` boxes, read from `data/lz-spike/s3.json`, which it polls every 500 ms (`mods/lz-spike/main.js`, `initS3`):
   - **A:** `data/lz-spike/a.jpg`, overwritten in place.
   - **B:** `data/lz-spike/b-<n>.jpg`, a unique name each time.
   - **C:** `mods/lz-spike/img/c.jpg`, overwritten in place under `mods/`.

   On a change it calls `cx.notify()`, so a stale picture is not a missed re-render.
2. Solid-color JPEGs (q90) made with `node /tmp/lz-spike/png.mjs make … solid:<rgb>` and `sips -s format jpeg`.
3. Initial state: A red `#e0302a`, B `b-1.jpg` green `#2fb344`, C blue `#2a5be0`. Shot `img/s3-1-initial.png`.
4. In place: `cp yellow.jpg data/lz-spike/a.jpg` and `cp magenta.jpg mods/lz-spike/img/c.jpg`. Wrote `b-2.jpg` (cyan `#1cd6e8`). Set `s3.json` to `{"b":"data/lz-spike/b-2.jpg","rev":2}`. Waited 2 s. Shot `img/s3-2-after-change.png`.
5. Switched to another tab and back, then shot `img/s3-3-reshown.png`.
6. Counted pixels of each color (tolerance 20) in the screenshots with `node /tmp/lz-spike/png.mjs count <png> <rrggbb> 20`.

## Evidence

The rendered view shows `S3 rev 2` and the three boxes. `img/s3-2-after-change.png` shows A red, B cyan, C magenta.

## Result

- **Unique names (required):** `b-1.jpg` → `b-2.jpg` shows the new picture at once. **Pass.**
- **Overwritten under `data/`:** stays stale, even after re-render and after the tab is hidden and shown again. [INFERENCE] Herdr caches decoded images by path and does not watch `data/`.
- **Overwritten under `mods/`:** updates by itself. This matches `H/AGENTS.md:902-905` ("Saving an asset under `mods/` updates every mod showing it").

## Consequence for implementation

- **Unique names:** as §5 and §6 of ARCHITECTURE.md already require:
  - PDF pages: `p<page>-w<width>-<seq>.jpg` with a rising `seq`.
  - Markdown images: content-addressed `cache/img/<sha1>.<ext>`.
  - Never rewrite a file a view may already show.
- **Never overwrite in place under `data/`:** the picture stays stale.
- **Do not use `mods/`:** an in-place overwrite there would update, but any file written under `mods/<mod>/` reloads every copy of that mod. Copying `c.jpg` at 17:35:21Z re-ran `init` of the hub, s1 and s3 copies (`data/lz-spike/init-args/s3-cyu03b.json`, `s1-w4rec9.json`, `hub-jp5x7j.json`, all 02:35:21 KST). Keep caches under `data/lazuli/`.
- **No fallback needed.**
