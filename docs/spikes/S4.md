# S4: `net` and `websocket` in a live window

**Verdict: Pass.** In the live window, a TCP round trip from a mod works, and so does a `ws://` WebSocket. Under `herdr-app check`, both throw synchronously, and an unguarded call fails the check.

Run 2026-11-19 in the live Herdr 0.1.16 window. Mod `lz-spike`, hub copy in tab `lz-hub` of space `lazuli-spike`.

## Question

Can a mod open a loopback TCP socket (the PDF daemon transport, ARCHITECTURE.md §5), and what do `websocket` and `herdr-app check` do?

## Steps

1. Started an echo server: `nohup node /tmp/lz-spike-s4/server.mjs &`.
   - TCP line echo on `127.0.0.1:49668`.
   - A minimal RFC 6455 echo on `127.0.0.1:49669` (`http` upgrade, unmasked replies).
   - Ports went to `/tmp/lz-spike-s4/port.json`.
   - Sanity check from Node's own clients: `tcp echo: "hi-한글\n"`, `ws echo: ws-한글`.
2. **Live TCP**, through the hub (`data/lz-spike/ctl.json` op `net`, code `netTest` in `mods/lz-spike/main.js`):
   - `import net from "net"`, then `await net.connect("127.0.0.1", port)`.
   - Then 20 × `await sock.write("ping-<i>-한글\n")`, then `await sock.read(65536)` until a newline. Bytes are decoded with `Buffer.from(bytes).toString("utf8")`. QuickJS has no `TextDecoder` (it is absent from `gpui-kit.d.ts`).
3. **Live WebSocket**: `import { WebSocket } from "websocket"`, then `await WebSocket.connect("ws://127.0.0.1:49669")`. Then 20 × `write(text)` / `read()`.
4. **Refused port**: `net.connect("127.0.0.1", 1)`.
5. **Under check**: `herdr-app check` on a staging copy, with the socket calls started synchronously in `init`, one kind at a time (`check-port.js` flags `checkNet` and `checkWs`).
   - First run: unguarded.
   - Later runs: wrapped in `try`.
   - Async steps traced with `exec("/bin/sh", …)` into `/tmp/lz-spike-s4/check-trace.log`.

## Result

| Item | Result |
|---|---|
| TCP round trip, live (required) | works; connect ≤4 ms, round trip 0–5 ms, UTF-8 intact |
| `websocket` `ws://` client, live | works; connect 3 ms, but ~54 ms per round trip after the first (11 ms) |
| Connection refused | the promise rejects with the OS error text |
| `net` / `websocket` under `herdr-app check` | throw synchronously: "network access … not granted"; uncaught in `init` → `check failed` |
| Async work under check | stops at the first awaited host call; later code is never exercised |

[INFERENCE] The ~54 ms WebSocket round trip comes from the client's read or write path. The echo server answers in under 1 ms for TCP. It is fine for occasional messages and too slow for chatty protocols.

## Consequence for implementation

- **PDF transport:** keep `net.connect` over TCP with line JSON as designed. No `pdfd --once` fallback is needed.
- **Never touch the network in check:** every `net.connect`, `WebSocket.connect` and `fetch` must sit behind `if (checking()) return;`, or inside a task that starts only when not checking. Otherwise `herdr-app check` fails (T01, T17).
- **Read paths:** decode bytes with `Buffer` from `"buffer"`; QuickJS has no `TextDecoder`. Keep partial lines across reads; `core/proto.js` already plans this.
- **No WebSocket on hot paths:** do not use `websocket` where round-trip latency matters. Nothing in the design needs it.
