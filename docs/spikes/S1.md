## Question

Can lazuli's HTML viewer (B7) run as a terminal pane split into a mod tab, and do these work there?

- Kitty graphics.
- SGR pixel mouse reports.
- A program-set title the mod can find.
- `pane.zoom` (Preview mode) and `pane.close` (Edit mode).

## Steps

1. **Mod tab:** `herdr-app do tab.new '{"space":"sp9dea2a22530987646a8818066d38da63","mod":"lz-spike","props":{"view":"s1"},"name":"lz-s1","focus":false}'` → `{"space":"sp9dea2…","tab":"tba3b9ada3994acfa113a4ef5f0a2d990b","pane":"pc2fdd633d167d8e25233dd57e1c7effd"}`.
2. **Probe pane:** `herdr-app do pane.split '{"direction":"right","pane":"pc2fdd633d167d8e25233dd57e1c7effd","argv":["node","/Users/lapis0875/.config/herdr-app/mods/lz-spike/bin/probe.mjs"]}'` → `{"pane":"pac669c2198a7d63140ba447d5e4cafaf","terminal":"t3z"}`. The owner's focus did not change (`herdr-app status` before and after).
3. **What the probe does** (`mods/lz-spike/bin/probe.mjs`). It writes:
   - `OSC 2;lz-probe` and `OSC 0;lz-probe`;
   - `CSI ?1049h`, `CSI ?1003h CSI ?1006h CSI ?1016h CSI ?1004h CSI ?2004h`;
   - kitty keyboard `CSI >1u`, then `CSI ?u`;
   - DECRQM `CSI ?<mode>$p` for each mode;
   - `CSI 16t` and `CSI 14t`;
   - a Kitty support query (`a=q`);
   - a 320×160 PNG (magenta/cyan checker, 6 px yellow border): `ESC _G a=T,f=100,t=d,i=1,p=1,q=0,C=1,m=…;<base64> ESC \`, in 4096-byte chunks.

   It appends every raw stdin chunk (hex + decoded) to `/tmp/lz-spike-s1/input.log` and logs signals to `/tmp/lz-spike-s1/signals.log`. It redraws on SIGWINCH.
4. **Shot, split:** saved the owner's focus, showed space `lazuli-spike` tab `lz-s1`, `herdr-app shot docs/spikes/img/s1-split.png`.
5. **Zoom:** `herdr-app do pane.zoom --pane pac669c2198a7d63140ba447d5e4cafaf`, then `herdr-app status`, `herdr-app shot docs/spikes/img/s1-zoomed.png`, then `pane.zoom` again to unzoom. Restored the owner's space, tab and pane.
6. **Title:** read `panes()` through the hub copy (`data/lz-spike/out/1.json`), plus `hc get t3z --json` and `herdr-app ls`.
7. **Close:** `herdr-app do pane.close --pane pac669c2198a7d63140ba447d5e4cafaf`, then read `signals.log` and `hc get t3z`.
8. **Left open:** moved the automated logs to `input-auto.log` / `signals-auto.log` and split a new probe → `{"pane":"p30d29ce82b90d3666c102e4f0839794e","terminal":"t42"}`. **It stays open for the manual part.**

## Manual steps (owner, about 3 minutes)

The probe pane (`p30d29ce82b90d3666c102e4f0839794e`, terminal `t42`) is open in space `lazuli-spike`, tab `lz-s1`. It logs to `/tmp/lz-spike-s1/input.log`.

2. Mouse:
   - Click inside the probe pane (left, then right).
   - Move the pointer over it.
   - Drag a little.
   - Scroll the wheel or trackpad up and down, then sideways.
3. Keyboard, with the probe pane focused:
   - Switch to the Korean input source and type `한글 테스트`, then Enter.
   - Press Esc, an arrow key, Backspace, Ctrl-C (the probe does not quit), and ⌘V with some text on the clipboard.
4. Run `node /tmp/lz-spike-s1/summarize.mjs`. Expected:
   - `mouse` counts for `press-left`, `release-left`, `move`, `wheel-up` and `wheel-down`;
   - `units: {"px": …}` (pixel reports from 1016) with `maxX`/`maxY` inside `textAreaPx`;
   - `text` entries whose codepoints are composed syllables (`U+D55C U+AE00` for 한글);
   - `keys` entries for Esc, the arrows and Ctrl-C (kitty `CSI … u` forms);

   Kitty reply fragments split across reads can also show up as `text` (`Gi=1,p=1;…`); ignore them.

## Consequence for implementation

- **B7 holds (T16):** a Node viewer in a terminal pane split beside the lazuli mod pane can draw Kitty PNG frames at 1:1 physical pixels and ask for SGR pixel mouse.
  - Size frames from `CSI 14t` and redraw on SIGWINCH. Zoom, Edit/Split/Preview and switching spaces all resize the terminal.
  - Hidden tabs are resized too: the probe flipped between 87 and 53 columns when the owner's space, with its right panel open, was shown.
- **Viewer discovery:** the `lazuli-view:<fid8>` title is visible in `panes()[i].title`, so §5's discovery works.
- **Edit mode:** `pane.close` ends the viewer with SIGHUP, so the viewer's SIGHUP handler is its cleanup path; §5 already plans it.
- **`main.js` (T01):** read the view from `props()`, not from `init`'s first argument.
- **Remaining risk:** pointer and IME input, pending the manual part. If it fails, the B7 fallback applies (owner decision).
