# S9: Hermes ACP handshake without tokens

**Verdict: Pass.** Every check item ran against the real Hermes 0.17.0, with zero model calls. Four findings change how K3, K4 and K6 must be built:

1. `session/load` of an unknown id **succeeds** with `{}`; it does not return an error (K4).
2. `sqlite3 -json` prints **nothing** for zero rows, not `[]` (K6).
3. `sqlite3 -readonly` fails with `unable to open database file (14)` after a clean Hermes exit removes `-wal`/`-shm` (K6).
4. `initialize` resolves provider credentials and can refresh the Codex OAuth token over the network. Here that took most of the 1.56 s cold start and rewrote `~/.hermes/auth.json` (K3).

Run on 2026-11-23 (macOS, Node 26.13.0). Hermes: `~/.hermes/hermes-agent`, `pyproject.toml` version 0.17.0, git `5ecf3bf0`, `agent-client-protocol` 0.9.0, ACP protocol 1. Tools: `/usr/bin/sqlite3` 3.54.0 (Apple), the Hermes venv's Python sqlite 3.50.4. Working folder: `/tmp/lz-s9`.

## Question

Can lazuli start `hermes -p default acp` and run the whole non-prompt surface without spending a token? That surface is `initialize`, `session/new`, `session/list`, `session/set_model`, `/help`, `/version`, `/context`, `session/fork` and `session/load` of an unknown id. The spike also asks:

- How long does the cold start take?
- What exact text acknowledges a steer?
- Which `SESSIONS_SQL` works on the live WAL `state.db`?

### SESSIONS_SQL

The working query, saved as `docs/spikes/S9/sessions.sql`:

```sql
SELECT
  s.id AS id,
  s.title AS title,
  COALESCE((SELECT SUBSTR(REPLACE(REPLACE(m.content, X'0A', ' '), X'0D', ' '), 1, 63)
            FROM messages m
            WHERE m.session_id = s.id AND m.role = 'user' AND m.content IS NOT NULL
            ORDER BY m.timestamp, m.id LIMIT 1), '') AS preview,
  CASE WHEN json_valid(s.model_config) THEN json_extract(s.model_config, '$.cwd') END AS cwd,
  s.model AS model,
  s.message_count AS message_count,
  s.started_at AS started_at,
  COALESCE((SELECT MAX(m2.timestamp) FROM messages m2 WHERE m2.session_id = s.id), s.started_at) AS last_active,
  s.input_tokens AS input_tokens,
  s.output_tokens AS output_tokens,
  s.cache_read_tokens AS cache_read_tokens,
  s.cache_write_tokens AS cache_write_tokens,
  s.reasoning_tokens AS reasoning_tokens,
  s.estimated_cost_usd AS estimated_cost_usd,
  s.actual_cost_usd AS actual_cost_usd,
  s.cost_status AS cost_status,
  s.api_call_count AS api_call_count
FROM sessions s
WHERE s.source = 'acp'
  AND s.message_count > 0
  AND s.archived = 0
  AND (s.parent_session_id IS NULL
       OR (json_valid(s.model_config) AND json_extract(s.model_config, '$._branched_from') IS NOT NULL)
       OR EXISTS (SELECT 1 FROM sessions p
                  WHERE p.id = s.parent_session_id AND p.end_reason = 'branched'
                    AND s.started_at >= p.ended_at))
  AND NOT (json_valid(s.model_config) AND json_extract(s.model_config, '$._delegate_from') IS NOT NULL)
ORDER BY last_active DESC, s.id DESC
LIMIT 1000;
```

## Result and consequence per contract

### K3 Bridge

**Result**

- `<abs hermes> -p default acp` with `cwd` = folder works.
- stdout is pure newline-delimited JSON-RPC from the first byte.
- `initialize` with `fs`/`terminal` off and `clientInfo` lazuli is accepted.
- Cold start to the `initialize` result: 0.56–0.74 s, or 1.56 s when Hermes refreshes the Codex token.
- One process, no children, no sockets left open while idle.
- SIGTERM ends it in 5 ms; EOF ends it with code 0 in about 0.1 s.

**Evidence:** Timings, Process gone, `01-initialize.jsonl`, `cold-start-run*.jsonl`.

**Consequence**

- The 45 s discovery wait holds. The worst case is the refresh timeout `HERMES_CODEX_REFRESH_TIMEOUT_SECONDS` (default 20 s, `hermes_cli/auth.py:3762`) plus the auth lock wait `max(15, 25)` s (`:67`, `:3769`). Keep 45 s; `init-timeout` should not fire before then.
- `session/new` adds about 2 s on top. The view should show a starting state until the first session exists, not only until the bridge is ready.
- The SIGTERM path in the shutdown rule needs no SIGKILL in the idle case. Keep SIGKILL as the fallback.
- A 16 MiB line cap is far above the observed 2.4 KB.
- **Conflict to settle (Main):** K3 says the log takes "the agent's stderr" and "never … message bodies". Hermes writes the first 100 characters of every model prompt to stderr at INFO (`server.py:1383`, `Prompt on session %s: %s`). Verbatim stderr logging would put message text into `<profile>.log`. Either drop that line pattern or accept it.

### K4 Service API

**Result**

- `session/new` returns `models` and `modes` with the current model marked.
- `session/list {cwd}` never lists empty sessions: in memory `session.py:302`, persisted `:333`.
- `session/set_model` returns `{}`, and returns `{}` for a missing session too (`server.py:2020-2021`, normalised by `acp/utils.py normalize_result`).
- `session/fork` returns a new UUID with `models` and `modes`. A fork of an unknown id returns `sessionId: ""` (`server.py:1232-1243`; source only, not exercised).
- `session/load` of an unknown id returns `{}` and no JSON-RPC error.
- Slash commands answer in about 1 ms with one chunk.

**Evidence:** `02`–`09` jsonl files and the stderr `load_session … not found`.

**Consequence**

- `select` must treat a `session/load` result without `models` as `not-found`; the `rpc:<code>` path never fires for it. Likewise `fork` must treat an empty `sessionId` as `not-found`.
- `setModel` cannot learn failure from the result. After `{}`, keep the chosen model in session state.
- `newSession`'s empty row can come only from local state, which K4 and K6 already assume.
- `/model <x>` and `session/set_model` both rebuild the AIAgent (`server.py:1760-1779`, `1989-2021`) without a model call.
- The model menu should mark the current model by `currentModelId`, not by parsing the description.

### K5 Chat model

**Result**

- The steer acknowledgement is `⏩ Steer queued for the active turn: <preview>` (`server.py:1964-1965`).
- Three related outcomes: `No active turn — queued for the next turn. (N queued)` (`:1973`), `⚠️ Steer failed: <exc>` (`:1968`), `Usage: /steer <guidance>` (`:1959`).
- Each arrives as a single `agent_message_chunk`, then `usage_update`, then `end_turn` for the steer request, interleaved with the running turn.
- A slash answer's `PromptResponse` has no `usage`.

**Evidence:** Steer acknowledgement table; `05`–`07` jsonl.

**Consequence**

- `assistant-agents.js` patterns, anchored at the chunk start:
  - `/^⏩ Steer queued for the active turn: /` = acknowledged;
  - `/^No active turn — queued for the next turn\. \(\d+ queued\)$/` = acknowledged but queued by Hermes;
  - `/^⚠️ Steer failed: /` = failed notice;
  - `/^Usage: \/steer /` = refused.
- Rule (5) can match the whole chunk text, because each acknowledgement is exactly one chunk.
- Rule (6): a steer's in-flight entry ends with its own `end_turn`, while the turn it steered keeps running under the earlier request id.
- Never send `/steer` to an idle session: Hermes turns it into a normal prompt (`server.py:1331-1350`). If the turn ends between Enter and arrival, the guidance runs as a new turn [INFERENCE from the same lines].
- `lastTurn` usage is absent for command turns.

### K6 List model

**Result**

- `SESSIONS_SQL` above runs on the live WAL DB with `/usr/bin/sqlite3 -readonly -json`.
- On synthetic rows it matches Hermes's own ACP listing (ids, titles, counts, order) except compression projection.
- It survives a malformed `model_config`; Hermes's listing does not.

**Evidence:** SESSIONS_SQL section.

**Consequence**

- `mapRows("")` must return `[]`: `-json` prints nothing for zero rows.
- On exit error containing `(14)` with no `<db>-wal` file, re-run with `file:<db>?immutable=1` (still `-readonly`). Otherwise fall back to `session/list` as K6 says. A profile without a connected bridge shows the error.
- Filter cwd in JS from `json_extract(model_config,'$.cwd')`; the `sessions.cwd` column is NULL for ACP rows.
- `started_at` and `last_active` are Unix seconds (REAL).
- Title fallback: title → preview (60 chars + `...`) → basename(cwd) → "New thread".
- `api_call_count`, tokens and cost come straight from the row. They are 0/NULL until a model turn runs.
- **Compression difference:** Hermes's listing replaces a compression root with its tip's id, title and counts (`hermes_state.py:2313-2339`). SESSIONS_SQL keeps the root.
