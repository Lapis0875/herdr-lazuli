# S6: Tab identity and `pane.split`

**Verdict: Partial.** Without a restart, each copy resolves its own tab, at first render, in all three opening paths. A hot reload does not break this either. Two parts are **Pending: needs restart**: the registry surviving a Herdr restart, and resolution after a restart. Steps for Main are below.

One correction to §10: `focused().tab` read **in `init`** is wrong in every case. It is the tab that was focused *before* the copy's tab was shown. Read it at first render, as §6 "Own ids" already says.

Run 2026-11-19 in the live Herdr 0.1.16 window. Mod `lz-spike`, view `s6`, space `lazuli-spike`.

## Question

Can a lazuli file-tab copy learn its own tab and pane? Does the shared registry survive? What does `herdr-app do tab.new` with `mod` print?

## Steps

The view (`mods/lz-spike/main.js`, `initS6` and `resolveS6`) works as follows:

- **In `init`:** logs `focused()` and `props()`.
- **On each render until resolved:** applies the §6 rule. `tab = focused().tab` is accepted when `panes()` has an `lz-spike` pane in that tab that no other `fid` claims in `shared("lzspike.s6reg")`. A resolved copy writes `{tab, pane, space}` there.
- **Logging:** each copy writes `data/lz-spike/s6/<fid>.json` every second.

1. Saved the owner's focus (`herdr-app status`).
2. Opened three tabs:
   - **A, from the CLI, focus true:** `herdr-app do tab.new '{"space":"sp9dea2…","mod":"lz-spike","props":{"view":"s6","fid":"A"},"name":"lz-s6-A","focus":true}'`.
   - **B, from a mod, focus true:** the hub copy calls `run("tab.new", {space, mod:"lz-spike", props:{view:"s6",fid:"B"}, name:"lz-s6-B", focus:true})`. This is lazuli's opener path.
   - **C, from the CLI, focus false.**
3. Took `herdr-app status` after each. Shot `img/s6-1-B-shown.png`.
4. Listed `data/lz-spike/s6/` while C was still hidden. Then `tab.select` C and shot `img/s6-2-C-shown.png`.
5. **Hot reload:** showed tab A, ran `touch mods/lz-spike/main.js`, waited 2.5 s, re-read all three logs.
6. Read `shared("lzspike.s6reg")` through the hub, and read `~/.config/herdr-app/shared.json` on disk.
7. Restored the owner's space, tab and pane.

## Consequence for implementation

- **When to resolve (T15, `sys/filetabs.js`, `file/file-tab.js`):** resolve own ids in `render`, never in `init`. The §6 rule works as written once it runs at render: `focused().tab` plus an unclaimed `lazuli` pane in that tab.
- **Registry first:** first look up `shared("lazuli.tabs")[props().fid]`. When it names a tab that still exists in `spaces()` and a `lazuli` pane in it, take that without looking at focus. This covers copies after a reload or a restart.
- **Openers:** the opener cannot use `run`'s return value: it is `null`, and `focused()` has not moved when it returns. The copy resolving itself at first render, as tested, is enough. The §10 fallback (`exec("herdr-app", ["do","tab.new",…])` for printed ids) is not needed. It remains available: the CLI prints `{space, tab, pane}` for a mod tab.
- **Placement:** a `focus:false` file tab has no copy until shown, so the registry entry for it is written by the opener (file, preview), and `tab`/`pane` are filled in at first show.
- **`main.js` (T01):** read `props()`, not the `init` argument.
